# Overdex Philosophy

Overdex exists to reduce cognitive load without reducing player agency.

It does not play Pokémon GO.

It helps players understand Pokémon GO.

---

# The Mission

The purpose of Overdex is simple:

**Help the player make better decisions with less effort.**

Every feature should support that mission.

If it increases complexity without increasing understanding, it does not belong.

---

# The Knowledge Ladder

Overdex grows knowledge one layer at a time.

```
Know

↓

Observe

↓

Remember

↓

Understand

↓

Assist
```

A higher layer must never replace the responsibilities of a lower one.

Knowledge is earned—not assumed.

---

# Facts Before Conclusions

Facts are valuable because they are objective.

Observation records facts.

Memory preserves facts.

History organizes facts.

Intelligence derives meaning.

Presentation communicates meaning.

Every conclusion should be traceable back to observable evidence.

---

# Confidence Over Certainty

Not every answer deserves complete confidence.

When confidence is high, Overdex should speak clearly.

When confidence is low, Overdex should explain why.

Honesty builds trust.

Certainty without evidence destroys it.

---

# The Player Comes First

The player makes the decisions.

Overdex provides information.

It should reduce cognitive load without replacing human judgment.

Good software assists.

Great software teaches.

Exceptional software helps people improve even after it is closed.

---

# Learn Before the Battle

The Pokédex exists for a reason.

The more the player understands before entering battle, the less assistance they will need during battle.

Knowledge is the foundation of intelligence.

---

# Observe During the Battle

Observe only what changes.

Do not repeatedly solve problems that have already been solved.

Observe visible facts.

Infer everything else from memory.

---

# Remember After the Battle

Battles should leave behind knowledge.

Every battle teaches something.

Overdex should remember what players reasonably cannot.

The application becomes stronger because it remembers—not because it guesses.

---

# Respect Attention

Attention is limited.

Every pixel should justify its existence.

Every sound should communicate something.

Every animation should have a purpose.

Silence is often the correct interface.

---

# Simplicity Wins

Complexity belongs inside the engine.

Clarity belongs at the interface.

The player should never experience the complexity required to produce a simple answer.

---

# The Game Boy Principle

The original Game Boy succeeded because it knew exactly what it wanted to be.

Simple.

Focused.

Predictable.

Immediate.

Overdex should feel the same way.

Every screen should have a purpose.

Every button should have one job.

Every interaction should feel natural.

---

# Respect Existing Architecture

Architecture is expensive knowledge.

Assume existing architecture is intentional.

Improve it only when a task explicitly requires it.

The easiest architecture to maintain is the architecture that changes for a reason.

---

# Build for the Future

Technology changes.

Frameworks change.

Platforms change.

Good ideas survive all of them.

Build systems that can evolve without abandoning the principles that created them.

Mirror Pokémon GO as it exists today.

Leave room for what it may become tomorrow.

---

# Guiding Principles

- Build first.
- Test what already exists.
- Show that it happened.
- One feature.
- One commit.
- One test.

Definitions are immutable.

State is mutable.

Recognizers recover evidence—they do not reject imperfect evidence.

My Binders document your relationship with Pokémon.

The Pokédex documents Pokémon.

---

# The Promise

Overdex will never pretend to know something it does not.

When it speaks, the player should know:

- what was observed,
- what was inferred,
- and how confident the application is.

Trust is not a feature.

Trust is the product.

---

# One Sentence

> **Learn before the battle. Observe during the battle. Remember after the battle. Understand the battle. Improve before the next one.**

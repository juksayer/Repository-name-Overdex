# Implementation Plan - Git #275: Countdown Publication

This plan establishes the **publication boundary** for Battle facts. It enables the Battle module to broadcast its perceptions to the rest of the instrument through a single, authoritative API without introducing any cross-layer dependencies.

## Objective
**Establish the publication boundary for Battle facts.**

## Proposed Changes

### Infrastructure Layer

#### [MODIFY] [DroidballService.kt](file:///home/sean/AndroidStudioProjects/Overdex/app/src/main/java/com/example/overdex/battle/observation/DroidballService.kt)
- **`DroidballFact`**: Add `data class CountdownWitnessed(val value: String) : DroidballFact()`.
- **`companion object`**: Add `fun emitFact(fact: DroidballFact)` which becomes the **single publication API** for Battle facts. It will use `_facts.tryEmit(fact)`.

### Battle Observation Layer

#### [MODIFY] [CountdownObserver.kt](file:///home/sean/AndroidStudioProjects/Overdex/app/src/main/java/com/example/overdex/battle/observation/CountdownObserver.kt)
- After creating a `CountdownWitness`, publish it through `DroidballService.emitFact(...)`.
- Retain the existing `Log.d(...)` for verification.
- Do not introduce any `Match`, UI, or persistence dependencies.

---

## Not Included
- Match integration
- Battle timeline
- Memory
- Intelligence
- BattleOverlay
- Persistence

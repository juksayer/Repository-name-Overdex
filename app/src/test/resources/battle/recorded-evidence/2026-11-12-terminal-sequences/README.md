Source-timed numeric OpenCV measurements from five original MP4 recordings. The source paths and hashes and scan hashes are retained per recording. No original archive is changed. Full frame streams retain gaps; baseline statuses are reconstructed from PTS. This fixture is an independent numeric sequence regression, not proof of runtime pixel equivalence, live capture availability, or observed zero HP. Separate pixel tests check the Kotlin flash extractor.

`pixels.json` records 14 native/INTER_AREA crop checks with SHA-256 and source PTS. `sequence-pixels.json` records 45 consecutive frames resized with OpenCV INTER_AREA to 672x1493, then cropped to factory opponent bounds (168,343)-(672,1209). The original video hashes are in scans.json.gz. `archive-provenance.json` identifies the byte-preserved original timeline members and explicitly approximate video alignment used only for test enrichment.

`factory-scans.json.gz` retains all 12,241 selected frames from the same five complete videos after an independent maximum-20-Hz selection, INTER_LINEAR resize to 672x1493 and factory opponent crop (168,343)-(672,1209). This time the features and statuses came from the compiled production `TerminalParticleFrameMeasurer.measurePixels`; the host callback only supplied the crop's ARGB pixels instead of `Bitmap.getPixels`. Source video hashes, original PTS, reader JAR hash and raw observation-file hashes are inside each recording's provenance. `factory-reader-provenance.json` records the exact compiled class hashes and probe source hashes.

Wall times use video-relative milliseconds and publication stream/sequence are test-only sequential identifiers. They are not device wall clocks or original capture publication metadata. Elapsed times are host execution measurements and do not establish phone CPU cost. Full-file scanning deliberately bypasses runtime assignment/overlay gates, so this tests pixel/sequence behavior, not live availability. Numeric fixtures do not re-run the pixel reader when its implementation changes; the separate pixel tests do, and full rescanning is needed to refresh corpus measurements after a reader change.
